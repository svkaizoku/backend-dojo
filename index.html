Why review practice?

Many backend interviews include a round where you review a teammate's pull request. Algorithm drills don't train that.

Usual prep

  • Algorithm puzzles that look nothing like production code
  • Bug lists in blog posts, with no way to test yourself
  • Another paid subscription for AI feedback

Backend Dojo

  • Small, realistic Spring, Kafka, Redis and SQL pull requests
  • An answer key with the line, why it matters, and the fix
  • Grading on the AI account you already have, or no AI at all

How it works

  1. 1

    Pick a pull request

    Choose a topic and a level, in Java or Kotlin. Each PR has a short description, like a real one.

  2. 2

    Write your review

    Cite lines, explain the impact, propose a fix, and put must-fix items before nits.

  3. 3

    Grade it

    Your AI compares your review with the answer key and rates how clearly you wrote it. Or run the free keyword check.

  4. 4

    Study the key

    Every planted issue is pinned to its line with why it matters, the fix, and further reading.

Add an exercise

Each exercise is a folder with the code and a small JSON answer key. A validator checks that every issue points at a real line, and CI runs it on every pull request.

  1. Write a short, realistic pull request with a few planted problems.
  2. Describe each problem: the line, why it matters, the fix, and keywords.
  3. Run node scripts/validate.mjs and open a pull request.

Write exercises yourself. Bug ideas are free to reuse, but other people's code and text usually aren't; link good sources instead.
